# SUB-2026-004 Fleet IoT telemetry hub

## Summary

A hub that ingests telemetry from 60,000 vehicle trackers for enterprise customers and exposes the data to customers through an API.

Sponsor: VP Enterprise Services. Lead architect: Lena Fischer. Request type: New system or platform. Tier 2 (Standard). Data classification: Internal. Service tier: Tier 3. Estimated cost: 0.9 million US dollars.

## Architecture

- Devices publish telemetry over MQTT to an ingestion gateway.
- The gateway validates and forwards messages to the managed Kafka platform.
- Customers read their fleet data through the enterprise API gateway.
- Device credentials are provisioned at manufacture.

## Non-functional requirements

60,000 devices, one message per 10 seconds. Availability 99.5 percent.

## Standards compliance matrix

| Requirement | Status | Note |
|---|---|---|
| STD-API-004 R6 | Deviation | Devices cannot hold a client certificate with mutual TLS. They use signed device tokens. Dispensation DISP-2026-003 requested. |
| STD-API-004 R3 | Met | Customer API is published through the gateway. |
| STD-INT-009 R2 | Met | Managed Kafka platform. |
| STD-OBS-006 R2 | Met | Structured logs with correlation identifiers. |

## Options considered

- **Replace the tracker hardware.** Meets the standard but costs 7 million dollars. Rejected.
- **Signed device tokens with short lifetime.** Compensating control for constrained hardware. Recommended.

## Decisions

### G2: Approved with conditions

Complete: 2026-03-31. Decided: 2026-04-14. Paused: 0 business days.

## Discussion and rationale

The Security Architect accepted device tokens for the ingestion path only. The customer-facing API must still meet the standard.
